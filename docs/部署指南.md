# Streamlit Cloud 部署指南

## 1. 部署结论

本项目入口为 `app.py`，适合部署为 Streamlit Cloud 演示应用。部署时需要将代码、预训练模型、建议库和示例数据一起提交到 Git 仓库。

当前系统使用本地 JSON 文件保存历史记录，适合单实例演示和测试。不建议将当前 JSON 存储方案用于多人并发的生产医疗系统，也不应将真实患者隐私数据上传到公开演示应用。

## 2. 部署前检查

### 必须存在的文件

```text
app.py
config.json
requirements.txt
config/suggestions.json
models/cnn_model.h5
models/ecg_risk_xgb_model.json
models/ecg_scaler.pkl
```

MIT-BIH 示例数据也应保留在仓库中：

```text
data/mitbih/mit-bih-arrhythmia-database-1.0.0/100.dat
data/mitbih/mit-bih-arrhythmia-database-1.0.0/100.hea
data/mitbih/mit-bih-arrhythmia-database-1.0.0/100.atr
data/mitbih/mit-bih-arrhythmia-database-1.0.0/100.xws
```

点击“加载示例数据”时，系统读取 `100.dat`，并要求同目录存在配套的 `100.hea`。

### Git 跟踪检查

模型文件当前已经被 Git 跟踪，不要把 `models/` 加入 `.gitignore`。Streamlit Cloud 从仓库部署时需要这些模型文件。

可以在本地检查：

```powershell
git ls-files models
```

预期至少包含：

```text
models/cnn_model.h5
models/ecg_risk_xgb_model.json
models/ecg_scaler.pkl
```

运行时产生的内容已加入 `.gitignore`，包括：

- `storage/records.json`
- `storage/waveforms/`
- `uploads/`
- `logs/`
- `.streamlit/secrets.toml`

## 3. requirements.txt

当前依赖列表覆盖应用运行所需的主要库：

- `streamlit`
- `numpy`
- `pandas`
- `matplotlib`
- `scipy`
- `wfdb`
- `neurokit2`
- `xgboost`
- `shap`
- `tensorflow`
- `plotly`
- `joblib`
- `scikit-learn`
- `reportlab`
- `seaborn`

`reportlab` 用于 PDF 报告生成，`seaborn` 由仓库中的既有分析脚本使用。

建议后续在确认版本兼容后固定依赖版本，以降低 Streamlit Cloud 重建环境时的变化风险。当前项目未锁定版本，TensorFlow、NumPy、XGBoost 和 SHAP 可能存在版本兼容差异。

## 4. Streamlit 配置

项目已有 `.streamlit/config.toml`，内容设置为浅色医疗蓝主题：

- `base = "light"`
- `primaryColor = "#1A5CFF"`
- `backgroundColor = "#F5F7FA"`
- `secondaryBackgroundColor = "#EAF0FF"`
- `textColor = "#1F2937"`

该配置不包含机器相关路径，可直接用于 Streamlit Cloud。

## 5. Secrets 模板

当前应用默认使用本地规则建议，不需要 Streamlit Secrets 才能启动。

项目提供模板：

```text
.streamlit/secrets.toml.example
```

如果未来接入需要密钥的大模型 API：

1. 在 Streamlit Cloud 的应用设置中添加 Secrets。
2. 不要把真实密钥写入 Git。
3. 不要提交 `.streamlit/secrets.toml`。
4. API 只应作为可选的结果文字润色能力，不能参与 ECG 风险等级判定。

模板中的字段仅为预留示例：

```toml
LLM_API_KEY = ""
LLM_ENDPOINT = ""
LLM_MODEL = ""
```

当前代码的 LLM 配置主要是界面配置项，默认分析流程不依赖外部 API。

## 6. 相对路径说明

`config.json` 使用相对路径，例如：

```json
{
  "model_path": "models/ecg_risk_xgb_model.json",
  "cnn_model_path": "models/cnn_model.h5",
  "scaler_path": "models/ecg_scaler.pkl",
  "data_dir": "data/mitbih/mit-bih-arrhythmia-database-1.0.0",
  "suggestions_path": "config/suggestions.json"
}
```

`src/config_utils.py` 会以项目根目录为基准解析这些路径，因此不依赖当前 Windows 本机的绝对路径。配置文件使用正斜杠，兼容 Streamlit Cloud 的 Linux 环境。

`app.py` 没有写死项目本机的绝对路径。

## 7. Streamlit Cloud 创建应用

1. 将项目推送到 GitHub 仓库。
2. 登录 Streamlit Community Cloud。
3. 创建新应用并选择对应仓库、分支和目录。
4. Main file path 填写：

```text
app.py
```

5. 选择 Python 运行环境后部署。
6. 等待依赖安装和应用启动。
7. 打开应用 URL，先检查左侧导航和模型状态。

如果依赖安装时间较长或内存不足，优先检查 TensorFlow 版本、模型文件大小和 Streamlit Cloud 当前资源限制。

## 8. 部署后功能检查

按以下顺序进行最小验收：

1. 打开“心电分析”页面。
2. 点击“加载示例数据”。
3. 确认示例文件显示为 MIT-BIH 100 号记录。
4. 点击“开始分析”。
5. 确认波形、R 峰、异常心拍和 12 项特征正常显示。
6. 确认 XGBoost 风险等级、CNN/XGBoost 置信度和复核状态显示。
7. 确认 SHAP 单样本图、全局重要性图、QRS/ST_shift 交互图和决策路径图显示；数据不足时应出现提示。
8. 分别下载 TXT 和 PDF 报告，确认文件能够打开。
9. 保存一条历史记录。
10. 进入“历史记录”，确认可以回看波形和 SHAP，并下载历史报告。
11. 打开“系统设置”，确认阈值和模型路径字段可以读取和保存。

## 9. Streamlit Cloud 中的存储限制

当前应用会在运行时写入：

- `storage/records.json`
- `storage/waveforms/`
- `uploads/`
- `logs/`

这些文件不应被视为永久可靠存储。应用重启、重新部署或实例迁移后，运行时文件可能丢失。模型、配置、建议库和静态示例数据应通过 Git 仓库部署，而不是依赖运行时生成。

如果用于多人访问，需要另外设计：

- 并发写入保护。
- 数据备份和恢复。
- 用户权限。
- 患者隐私保护。
- 数据保留和删除策略。
- 更可靠的持久化存储方案。

## 10. 当前功能和限制

- 仅支持单导联 ECG，不支持 12 导联输入。
- 支持 CSV、TXT、DAT 文件；DAT 需要配套 HEA 文件。
- 支持 MIT-BIH 100 号示例数据。
- 系统使用预训练模型推理，不在线训练。
- 两条通路独立输出，不自动融合预测。
- 健康建议默认使用本地离线 JSON 规则。
- 当前训练数据量有限，评估指标仅供参考。
- XGBoost 高危样本敏感性在现有评估中“未能验证”。
- CNN 各类型心律失常敏感性“未能验证”。
- 当前不存在永久公网生产部署保障。
- 系统是辅助筛查工具，不能替代执业医师诊断。

## 11. 部署故障排查

### 找不到模型文件

检查 `models/` 是否已提交并被 Git 跟踪：

```powershell
git ls-files models
```

同时确认 `config.json` 中模型路径使用相对路径。

### 找不到示例数据

确认以下文件位于同一目录：

```text
100.dat
100.hea
```

并确认 `config.json` 的 `data_dir` 指向正确的 MIT-BIH 数据目录。

### PDF 生成失败

确认 `requirements.txt` 包含：

```text
reportlab
```

中文字体由运行环境自动寻找。若运行环境没有可用中文字体，PDF 可能出现中文显示问题，应在部署日志中检查字体注册错误。

### 应用启动后页面报错

检查 Streamlit Cloud 日志，重点查看：

- 依赖安装失败。
- TensorFlow 或 NumPy 版本冲突。
- 模型文件没有提交。
- 配置路径拼写错误。
- 运行时目录没有写权限。

## 12. 安全与医疗合规提示

不要在公开 Streamlit Cloud 应用中上传真实、可识别的患者数据。演示时使用脱敏信息和公开数据。

系统输出仅用于辅助筛查参考。所有风险等级、复核状态、SHAP 解释和健康建议都必须由专业医护人员结合临床资料审核，不得直接作为诊断、治疗或急救依据。
